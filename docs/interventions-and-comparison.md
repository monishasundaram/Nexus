# Interventions and comparisons (model v1.0.0)

## Interventions
An intervention is a list of modifications stored on a scenario version. They are applied to a COPY of the graph
when the version is simulated; the stored environment is never changed. Order: all `add_node` first, then every
other modification in list order. New nodes get ids above the existing ones and are marked `added` in the snapshot.

| Modification | Effect |
|---|---|
| set_capacity | node capacity = value |
| reduce_demand | declared demands (or the plain demand) x (1 - pct/100) |
| add_node | a new node (operational, no demands) placed below the graph |
| add_edge | a new connection; source and destination may be existing nodes or nodes added in the same list |
| set_edge | new strength and/or type for an existing connection |

Recovery or restoring a road is a scenario EVENT, not a modification. Events can only target existing nodes.

## Comparisons
Simulations are compared at each run's own peak step. The first simulation is the reference.
- Refused: fewer than 2 or more than 6, duplicates, different environments, different model versions.
- Adjusted score: the impact score computed only over nodes present in every run, using each run's own baseline
  levels and importance. Added nodes would otherwise dilute the raw score.
- Warnings: environment edited between runs, baselines differ, different events or peaks, non-converged solves,
  unequal baseline shortfalls, different node sets.
- "Why" text is generated by fixed rules from stored results: the biggest level change, the path along which the
  worse run loses service, the first node on that path where the two runs differ, and any modification that
  touches that node or one of its suppliers.

Not modelled: cost, physical feasibility, operations, or whether an intervention could really be built.
